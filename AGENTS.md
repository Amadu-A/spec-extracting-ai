# Правила работы в этом репозитории

- Перед изменением сверять актуальные локальные файлы, Git diff, контракты и текущие инструкции `main` репозитория `Amadu-A/shared_infrasktructure`, начиная с `docs/LLM_CONTEXT.md`. Команды/код пользователя проверять по фактическим файлам.
- Не выполнять commit/push и не менять shared stack без прямой команды владельца. Не создавать дополнительные модели, RabbitMQ, Redis или n8n.
- Владелец разрешил scripts/up.sh автоматически создавать выделенных пользователя/vhost этого приложения в существующем RabbitMQ по образцу contract-diff-search. Существующий пароль проверяется, без автоматической смены; чужие пользователи/vhost и shared configuration не меняются.
- Сохранять Ports & Adapters/DI. Web UI и интеграции используют один REST API и одинаковые use-case. Ключевые изменения покрывать unit, functional, regression, architecture, integration, security и E2E-проверками по смыслу изменения.
- Документация и docstrings собственных компонентов — на русском, относительный путь — первой допустимой строкой комментария.
- Все env читает Settings: `.env.example` → `.env` → окружение процесса. В `.env` — только секреты. Не читать/выводить пароли из других проектов. `examples/` и реальные outputs не добавлять в Git.
- Внутренние большие успешные прогоны направлять в `.log` и читать хвост/ошибки. Скрипты пользователя по умолчанию показывают логи.
- Использовать `ops/check-quality.ps1`, `scripts/test.sh`, `scripts/up.sh`; не добавлять entrypoint-скрипты без необходимости.
- В финальном ответе давать Windows quality/commit/push команды, Linux pull/test/rebuild команды и конкретные ручные проверки. Git add — только явные пути; commit/push выполняет пользователь.
- Не выдавать doubles/offline проверки за реальные VLM/AMQP прогоны. Фактические результаты и ограничения записывать в reports/.
