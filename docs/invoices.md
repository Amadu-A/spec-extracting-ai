# Счета и финансовые спецификации: invoice_extraction.v1

Сценарий «Извлечение счетов» работает в существующем сервисе на порту 8083.
Загрузка PDF/JPEG/PNG, обработка страниц, проверка сумм и оба экспорта доступны
через `/api/v1/invoice-extractions`; браузер использует тот же API.
Сценарий спецификаций, его восемь полей, Excel-шаблон и prompt не расширяются.

## Использование API

```bash
curl --fail-with-body -X POST http://192.168.55.3:8083/api/v1/invoice-extractions \
  -H 'X-API-Key: <отдельный ключ интеграции>' \
  -H 'Idempotency-Key: purchase-import-001' \
  -F 'files=@invoice.pdf;type=application/pdf' \
  -F 'files=@scan.png;type=image/png' \
  -F 'page_selection={"0":"1-3"}'
```

Ответ `202` содержит `job_id`, прогресс по каждому файлу и `links`. Без
`page_selection` выбираются все страницы. Ключи словаря — индексы файлов с нуля,
значения — диапазоны физических страниц с единицы. Общий лимит страниц пакета —
существующий `MAX_SELECTED_PAGES=100`; отдельный бюджет worker не увеличивается.

С тем же API credential запрашивайте `GET /{job_id}` до terminal state, затем
`GET /{job_id}/result.json` или `/result.xlsx`. Полный список операций и вложенные
схемы доступны в `/docs` и `/openapi.json`. Также поддерживается Bearer.
Реальные ключи хранятся только в `.env`/Settings и не передаются в JS.

| Операция относительно namespace | Назначение |
|---|---|
| `GET /{job_id}` | Статус, counts, файлы/страницы, expiry, links |
| `GET /{job_id}/snapshot` | Диагностика, raw stream и восстановление UI; partial не результат |
| `GET /{job_id}/result.json` | Один `invoice_extraction.v1` для всех файлов и документов |
| `GET /{job_id}/result.xlsx` | Листы «Документы», «Позиции», «Предупреждения» |
| `GET /{job_id}/warnings?offset=0&limit=100` | Пагинированные причины и координаты |
| `GET /{job_id}/events?after=0` | SSE replay, также Last-Event-ID |
| `GET /{job_id}/files/{file_index}/pages/{page}/preview` | Защищённый PNG оригинального листа |
| `POST /{job_id}/cancel` | Идемпотентная отмена |
| `POST /{job_id}/files/{file_index}/pages/{page}/retry` | Повтор листа и зависимого суффикса этого файла |
| `GET/PUT /prompt`, `POST /prompt/restore` | Отдельный prompt только текущей web-сессии |

Cookie capability и CSRF остаются общими, owners интеграций и браузера разделены.
Чужой ресурс или другой профиль — `404`; истёкший — `410`. Незавершённый,
отменённый или failed batch не выдаётся как полный результат (`409 result_not_ready`).
Тот же Idempotency-Key и те же байты/имена/страницы/prompt возвращают прежний job;
изменённый payload даёт `409`. API-ключи не заменяются браузерным cookie.

## Результат и проверка

Корневые поля: `schema_version`, `files`, `summary`. Каждый `files[]` содержит
`file_index`, `source_file`, SHA256 исходных байт, `page_count`, `documents[]`.
Порядок файлов соответствует загрузке. У каждого документа свои реквизиты,
позиции, итоги, проверки и физические `source_pages`/`attached_pages`.
Итоги разных контрагентов не объединяются. GUID 1С не создаётся.

Количество и деньги — десятичные строки, неизвестные значения — `null`.
Backend не восстанавливает отсутствующие суммы умножением округлённой цены.
Проверки `Decimal` сравнивают суммы строк с итогами, нетто+НДС с брутто,
quantity×price с опубликованной строкой. Допуск последней проверки зависит от
фактической точности цены: половина единицы последнего разряда × |quantity| + 0.01.
Явные внешние корректировки учитываются один раз; скидка в цене повторно не вычитается.
Для текстового PDF пометка «Вам предоставлена скидка … на … руб.» подтверждает
`included_in_line_totals=true` только для скидки с той же напечатанной суммой.
Будущая/условная формулировка таким доказательством не считается. Суммы строк и итогов
при этом не меняются и не используются для выбора этого признака.

Статусы проверки документа: `passed`, `partially_checked`, `failed`,
`not_checkable`. Неизвестное значение проверки — `null`, не `0.00`.
Доказанное арифметическое расхождение не исправляется: документ остаётся в полном
результате с failed-проверкой и статусом job `completed_with_warnings`.
Потерянная/нечитаемая выбранная страница блокирует финализацию всего пакета.

Артикул из явной графы/пометки отделён от кода поставщика и кандидата в конце
наименования. Смешанная графа сохраняется в `product_reference_raw`.
Для текстовых PDF заголовки/ячейки дополнительно сверяются по физической таблице;
числовые противоречия модели и источника видны в предупреждениях. В сканах
используется vision общей модели. Для платёжной строки скана без количества/единицы
выполняется отдельное чтение финансовых граф той же VLM по компактной схеме;
оно не вычисляет отсутствующие суммы и не подгоняет арифметику. Оба реальных потока
и измерения доступны в диагностике. Общий процент из итогов переносится только
в незаполненную ставку с `vat_rate_source=document_total` и явным `field_origin`.
Итоговые НДС/брутто не копируются в единственную строку без соответствующих граф.
Одинаковые коды разных физических строк сохраняются. Соглашения о поставке и
технические приложения не создают новые товары.

Excel сохраняет текст как текст, включая формулоподобные значения; отсутствующие
числа остаются пустыми. Значения длиннее точности Excel в 15 цифр сохраняются
текстом для предотвращения потери исходной точности.

## Архитектура и эксплуатация

`domain/invoices` — DTO/арифметика/происхождение/переносы;
`application/invoices` — use-case и профиль общего processor;
`infrastructure/invoices` — нормализация изображений, VLM-профиль и новая книга;
`presentation/http/invoice_*` — HTTP/OpenAPI;
`resources/prompts/invoices` — отдельные версионированные ресурсы;
`web/*/invoices*` — независимый state/controller с общими viewer/prompt/SSE.

В `app/bootstrap.py` оба профиля подключены к тем же repository/storage/PDF,
HTTP pool модели и единственной очереди `specification.extractions`. `job_type`
выбирает профиль в сохранённом snapshot; старый snapshot без discriminator читается
как спецификация. Alembic-миграция не требуется. TTL всех файлов одного batch
обновляется в транзакции задания. Recovery/lease/отмена общие, retry ограничен,
другие файлы не обрабатываются повторно без необходимости.

`INVOICE_MAX_FILES=10`, `INVOICE_MAX_BATCH_MB=100`, `INVOICE_MAX_PAGE_RETRIES=5`
объявлены в Settings и `.env.example`. `MAX_UPLOAD_MB=50` действует на каждый файл,
`RETENTION_SECONDS=3600` — на весь результат после terminal. `.env` менять не нужно.
JPEG/PNG сохраняются как исходные байты и нормализованная PDF-копия в том же
приватном UUID-каталоге; pixel limits проверяются до декодирования. Общие сервисы,
Mapper, 1С и конфигурация инфраструктуры не меняются.

Развёртывание и quality gate остаются прежними:

```powershell
.\ops\check-quality.ps1 -Browser -Docker
git diff --check
```

```bash
bash scripts/test.sh --browser --docker && bash scripts/up.sh
```

Для реальной сверки локального конфиденциального корпуса:

```bash
uv run --frozen pytest tests/test_live_invoices.py --vlm --require-invoice-corpus -q
uv run --frozen pytest tests/test_invoice_browser.py -k real_invoice_batch --vlm --require-invoice-corpus -q
```

Нужны семь PDF/JSON в `examples/invoices/` и доступ к shared-vlm по Settings.
Этот тест использует реальные PDF, repository/PDF/HTTP/worker use-case и VLM,
но прямой test-dispatch вместо AMQP. Он не доказывает серверный деплой или
реальное соединение RabbitMQ. Отчёты и outputs — только `reports/live/invoices/`.
Исходные реквизиты/документы не попадают в Git; CI использует синтетические fixtures.

Сверка требует точного совпадения количества строк, кодов, артикулов, числовых полей,
физических страниц и статуса арифметики. Различия переносов/пробелов в названиях,
`ё/е`, точки после обозначения года и запятой перед «согласно» записываются отдельно
в `formatting_differences`; регистр кодов, дефисы и прочие символы не игнорируются.
Дополнения к пустым полям эталона (например, КПП из договорного приложения)
записываются в `source_enrichments` и проверяются по тексту и физическим ячейкам PDF:
линейный текст может разрывать перенос производителя соседними числовыми графами.
Эталонные JSON автоматически не переписываются. `--require-invoice-corpus` прерывает
проверку при отсутствии любого из семи комплектов вместо незаметного skip.
